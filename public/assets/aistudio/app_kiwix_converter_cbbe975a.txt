PROJETO: ZIM TEXT CONVERTER

Conversor profissional de arquivos Kiwix/ZIM para bibliotecas Markdown exclusivamente textuais

1. VISÃO GERAL DO PROJETO

Desenvolva um aplicativo profissional, completo e funcional, especializado em converter arquivos ".zim" da plataforma Kiwix/OpenZIM para o formato Markdown ".md", preservando integralmente, dentro das possibilidades técnicas, o conteúdo textual, a organização, os metadados, os links internos, os redirecionamentos e a estrutura lógica das bibliotecas originais.

O aplicativo deverá ser projetado especificamente para criar bibliotecas de conhecimento exclusivamente textuais.

REGRA ABSOLUTA: NÃO EXTRAIR, NÃO COPIAR E NÃO EXPORTAR ARQUIVOS DE MÍDIA.

O resultado da conversão deverá conter somente documentos de texto Markdown.

Não exportar:

- Fotografias.
- Imagens.
- Ilustrações.
- Diagramas gráficos.
- Vídeos.
- Áudios.
- Animações.
- Miniaturas.
- Ícones.
- Arquivos SVG.
- Fontes.
- CSS.
- JavaScript.
- Arquivos binários.
- Recursos gráficos auxiliares.

O foco é converter o conhecimento armazenado nos arquivos ZIM em uma biblioteca leve, organizada, portátil, fácil de editar, pesquisar e utilizar offline.

O projeto deverá preservar o máximo possível das informações textuais originais, inclusive títulos, subtítulos, descrições, categorias disponíveis, referências, links, identificadores, caminhos e redirecionamentos.

Não transformar a biblioteca inteira em um texto desorganizado.

A organização original deverá ser preservada e reconstruída em uma estrutura Markdown lógica e navegável.

2. PLATAFORMA E TECNOLOGIAS

Desenvolver prioritariamente um aplicativo Android nativo.

Tecnologias preferenciais:

- Kotlin.
- Jetpack Compose.
- Android Studio.
- Android SDK.
- Android NDK.
- C++ para integração nativa.
- JNI para comunicação entre Kotlin e C++.
- libzim oficial para leitura dos arquivos ZIM.
- Parser HTML compatível com HTML5.
- Conversor HTML para Markdown.
- CommonMark.
- GitHub Flavored Markdown (GFM).
- SQLite FTS5 para pesquisa interna, quando disponível.
- Storage Access Framework para seleção e gravação de arquivos.
- UTF-8 para todos os documentos gerados.

Verificar a compatibilidade real da libzim com o ambiente Android escolhido antes de iniciar sua integração.

Utilizar APIs oficiais e documentadas sempre que possível.

Não criar leitores ZIM improvisados caso a biblioteca oficial consiga fornecer as informações necessárias.

A arquitetura deverá permitir futura expansão para Windows, Linux e macOS.

3. FUNCIONAMENTO 100% LOCAL

Todos os processos deverão acontecer localmente no dispositivo.

Não utilizar:

- Servidores externos.
- Conversores online.
- APIs remotas.
- Serviços de nuvem.
- Processamento remoto.
- Envio de documentos para terceiros.
- Dependências de conexão com a internet.

O usuário deverá conseguir selecionar um arquivo ZIM, realizar sua conversão completa e salvar a biblioteca Markdown sem conexão com a internet.

Não exigir conexão para:

- Abrir o ZIM.
- Ler as entradas.
- Converter HTML.
- Gerar Markdown.
- Resolver redirecionamentos.
- Converter links.
- Criar índices.
- Pesquisar documentos.
- Exportar arquivos.
- Validar o resultado.

O aplicativo poderá utilizar bibliotecas e dependências incorporadas durante sua compilação, mas não deverá precisar baixar componentes durante a conversão.

5. MECANISMO DE LEITURA E FILTRAGEM TEXTUAL

Desenvolver um leitor capaz de percorrer todas as entradas de usuário disponíveis no arquivo ZIM.

A primeira etapa será identificar o conteúdo de cada entrada, sua natureza e seu MIME type.

Em seguida, classificar os itens.

Conteúdos elegíveis para conversão

- Artigos HTML.
- Páginas XHTML.
- Textos HTML.
- Arquivos TXT.
- Conteúdo textual simples.
- Páginas de documentação.
- Artigos enciclopédicos.
- Documentos de conhecimento.
- Textos técnicos.
- Páginas de navegação.
- Conteúdo XML textual, quando aplicável.
- Outros conteúdos que possam ser interpretados com segurança como texto.

Para documentos textuais que não sejam HTML, desenvolver conversores específicos quando necessário.

Para PDFs, oferecer uma opção de extração do texto selecionável, sem exportar páginas como imagens. O OCR deverá ser opcional, local e desativado por padrão.

Não presumir que toda entrada com determinado MIME seja necessariamente texto legível.

Conteúdos que deverão ser excluídos da exportação

Todos os recursos binários ou exclusivamente multimídia.

Exemplos:

- image/jpeg.
- image/png.
- image/webp.
- image/gif.
- image/svg+xml.
- video/mp4.
- video/webm.
- audio/mpeg.
- audio/ogg.
- application/octet-stream.
- Arquivos de fontes.
- Arquivos gráficos.
- Arquivos de estilo.
- Arquivos de execução.
- Outros tipos não textuais.

A classificação deverá considerar o MIME type, a assinatura real do conteúdo quando necessário e a possibilidade de interpretação textual.

Não confiar exclusivamente na extensão do arquivo.

Regra de segurança

Os conteúdos classificados como não textuais não deverão ser completamente extraídos para o diretório de saída.

O sistema poderá consultar informações mínimas necessárias para classificá-los, identificar seus nomes, caminhos e relacionamentos, mas não deverá criar cópias desses arquivos.

TABLE| Tabela Markdown

Preservar também:

- Parágrafos.
- Quebras de linha.
- Listas aninhadas.
- Tabelas.
- Notas de rodapé.
- Referências.
- Citações.
- Fórmulas matemáticas.
- Símbolos especiais.
- Caracteres Unicode.
- Acentuação.
- Equações.
- Blocos de programação.
- Exemplos técnicos.
- Textos de advertência.
- Legendas textuais.
- Informações bibliográficas.

Utilizar HTML inline somente quando não houver uma representação Markdown adequada.

O objetivo é preservar a informação e a leitura, não reproduzir visualmente uma página HTML.

Não alterar o significado dos textos.

Não remover parágrafos automaticamente.

Não duplicar textos devido a elementos aninhados.

Não inverter a ordem dos conteúdos.

Não converter elementos semânticos em texto genérico sem necessidade.

7. TRATAMENTO ESPECIAL DE ELEMENTOS MULTIMÍDIA

Esta função deverá ser rigorosamente implementada.

Ao encontrar conteúdo multimídia dentro de um artigo, o aplicativo deverá excluir o arquivo e preservar somente as informações textuais relevantes.

Imagens

Ao encontrar:

- IMG.
- PICTURE.
- SOURCE.
- FIGURE.
- SVG.
- CANVAS.

Não exportar a imagem ou o conteúdo gráfico.

Preservar, quando disponíveis:

- Texto ALT.
- Descrição textual.
- Título da figura.
- Legenda.
- Créditos textuais.
- Referências textuais.

Exemplo:

HTML original:

<figure>
  <img src="imagem.jpg" alt="Mapa do Brasil">
  <figcaption>Mapa político do Brasil.</figcaption>
</figure>

Resultado Markdown:

> [Imagem não exportada: Mapa do Brasil]
>
> Legenda: Mapa político do Brasil.

Se não houver descrição ou legenda, não criar textos fictícios.

Oferecer uma configuração para remover completamente os marcadores de imagens, mantendo apenas os textos que já existiam no artigo.

Vídeos

Remover o arquivo de vídeo e preservar:

- Título.
- Descrição.
- Legenda textual.
- Transcrição já existente.
- Informações relevantes em texto.

Exemplo:

> [Vídeo não exportado: Introdução ao assunto]

Áudios

Remover os arquivos de áudio e preservar:

- Título.
- Descrição.
- Transcrição original, quando disponível.
- Legendas.
- Informações textuais relacionadas.

Não executar reconhecimento de voz automaticamente.

Arquivos de mídia sem legenda

Registrar a ocorrência no relatório de exclusões, sem adicionar informações inventadas ao artigo.

JavaScript, CSS e fontes

Não copiar nem executar esses arquivos.

Remover as dependências visuais e de execução da página, mantendo exclusivamente o conteúdo textual legível.

9. SISTEMA DE REDIRECIONAMENTOS

Esta é uma das funcionalidades mais importantes do projeto.

Preservar todos os redirecionamentos existentes no arquivo ZIM, incluindo aliases, nomes alternativos e cadeias de redirecionamento.

Consultar o destino real das entradas utilizando os recursos próprios da biblioteca de leitura.

Para cada redirecionamento, identificar:

- Título original.
- Caminho original.
- Destino imediato.
- Destino final.
- Título do destino.
- Caminho Markdown correspondente.
- Quantidade de etapas.
- Estado da resolução.
- Possíveis ciclos.
- Destinos inexistentes.

Exemplo

Origem:

A/Linux

Primeiro destino:

A/GNU_Linux

Segundo destino:

A/Sistema_Operacional

Destino final:

A/Sistema_Operacional

Resultado:

Arquivo "redirects/Linux.md":

---
title: "Linux"
type: "redirect"
original_path: "A/Linux"
redirect_target: "../articles/Sistema_Operacional.md"
---

# Linux

Este documento é um redirecionamento para outro artigo.

[Acessar o artigo original](../articles/Sistema_Operacional.md)

Criar um documento Markdown próprio para cada alias, quando configurado.

Não juntar todos os aliases em um único artigo.

Requisitos especiais

- Preservar redirecionamentos em cadeia.
- Preservar a relação entre origem e destino imediato.
- Registrar o destino final.
- Detectar ciclos.
- Detectar autorreferências.
- Detectar destinos ausentes.
- Não eliminar aliases.
- Não perder nomes alternativos.
- Evitar duplicações.
- Preservar caminhos originais.
- Gerar links locais.
- Preservar o relacionamento mesmo que o destino não possa ser convertido.

Se o destino for uma imagem, vídeo ou outro recurso excluído, registrar que o destino não possui representação exportada.

Não criar um link Markdown quebrado.

Gerar um aviso explicando que o redirecionamento aponta para um recurso não textual que não faz parte da biblioteca final.

Navegação dos redirecionamentos

Criar um mecanismo próprio de navegação no leitor interno do aplicativo.

O mecanismo deverá consultar o arquivo "REDIRECTS.md" ou seus registros internos para encontrar o destino correto.

O sistema deverá permitir abrir um alias e chegar ao documento original sem depender de internet.

10. SISTEMA DE LINKS INTERNOS

Converter os links internos existentes no ZIM para referências relativas entre documentos Markdown.

Exemplo:

Original:

<a href="../A/Historia">História</a>

Resultado:

[História](../articles/Historia.md)

Resolver os links considerando:

- Caminho original.
- Caminho de origem.
- Caminho de destino.
- Título.
- Namespace.
- Caracteres especiais.
- Espaços.
- Acentos.
- Codificação URL.
- Parâmetros de consulta.
- Fragmentos.
- Redirecionamentos.

Não utilizar a internet para resolver links internos.

Não gerar links que apontem para documentos inexistentes.

Links internos para conteúdos textuais

Converter normalmente para arquivos Markdown.

Links internos para mídias excluídas

Preservar o texto do link, mas remover o destino clicável quando o arquivo não existir no pacote.

Exemplo:

Original:

<a href="audio.mp3">Ouvir gravação</a>

Resultado:

Ouvir gravação [áudio não exportado].

O texto original do link deverá permanecer disponível.

Links externos

Preservar os endereços originais.

Exemplo:

[Documentação oficial](https://exemplo.com)

Não baixar o conteúdo externo.

Âncoras

Preservar referências a seções específicas.

Exemplo:

[Consultar capítulo](../articles/historia.md#segunda-guerra-mundial)

Criar um mapeamento entre IDs HTML originais e âncoras Markdown.

Tratar títulos duplicados, acentos e identificadores personalizados.

Quando não for possível reconstruir exatamente uma âncora, registrar a ocorrência no relatório.

14. FORMAS DE EXPORTAÇÃO

Criar diferentes modalidades.

Modo A — Biblioteca Markdown organizada

Opção padrão.

Criar uma pasta com documentos ".md" individuais, preservando caminhos, artigos, categorias, índices e redirecionamentos.

É o modo recomendado para bibliotecas grandes.

Modo B — Arquivo Markdown único

Reunir todos os documentos textuais em um único ".md".

Organizar o documento por:

- Título.
- Categorias.
- Seções.
- Subtítulos.
- Artigos.
- Conteúdos relacionados.

Inserir separadores claros entre os artigos.

Exemplo:

# BIBLIOTECA COMPLETA

## Categoria 01

### Artigo 001

Conteúdo...

---

### Artigo 002

Conteúdo...

---

## Categoria 02

### Artigo 003

Conteúdo...

Não perder a identificação dos artigos originais durante a união.

Preservar links internos utilizando âncoras locais quando possível.

Criar identificadores exclusivos para títulos repetidos.

Modo C — Markdown dividido por categorias

Criar um arquivo ".md" por categoria, mantendo os artigos organizados em seções.

Modo D — Markdown otimizado

Gerar uma biblioteca com o menor tamanho textual possível, removendo espaços excessivos, marcações desnecessárias e elementos de formatação redundantes, sem remover informações relevantes.

Modo E — Conversão personalizada

Permitir ao usuário selecionar quais conteúdos textuais serão convertidos.

O modo exclusivamente Markdown não deverá incluir mídias em nenhum desses formatos.

27. ORIENTAÇÃO FINAL E PRIORIDADE ABSOLUTA

Desenvolva este projeto como um software profissional de preservação e transformação de conhecimento digital.

A prioridade máxima é transformar bibliotecas Kiwix/ZIM em bibliotecas Markdown exclusivamente textuais, leves, organizadas, pesquisáveis e portáteis.

O aplicativo deverá preservar o conhecimento, não as mídias.

Os artigos e seus relacionamentos devem continuar compreensíveis e navegáveis mesmo depois da remoção de todas as imagens, vídeos, áudios e arquivos binários.

A organização não pode ser sacrificada para reduzir o tamanho.

Os redirecionamentos não podem ser descartados.

Os links internos não podem ser simplesmente apagados.

Os metadados não podem ser perdidos.

Os conteúdos textuais não podem ser agrupados aleatoriamente.

A biblioteca deverá manter a identificação de cada artigo e permitir localizar seus documentos por título, categoria, caminho original e aliases.

A exportação deverá ser composta somente por arquivos Markdown, sem depender de recursos externos.

O aplicativo deverá oferecer duas experiências principais:

1. Biblioteca Markdown organizada: vários documentos ".md", índices e redirecionamentos preservados.

2. Markdown único: todos os textos reunidos em um documento organizado e pesquisável.

A solução final deverá ser leve, eficiente, segura, completamente offline e capaz de converter arquivos ZIM grandes sem consumir desnecessariamente a memória do dispositivo.

O objetivo é criar uma ferramenta de conversão realmente confiável, que transforme bibliotecas ZIM em arquivos Markdown puros, preservando ao máximo sua organização e seu conteúdo textual original.
